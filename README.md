# AI Folder Organizer

FastAPI and React application for authenticated, user-scoped folder scanning
and file-content extraction. Passwords use Argon2id. Access tokens are signed
JWTs; refresh tokens are random values stored only as hashes in MySQL and sent
to browsers in an HTTP-only cookie.

## Configure and run

From the backend directory, copy `.env.example` to `.env`. Set the MySQL
credentials and replace `JWT_SECRET` with a random value generated by:

```powershell
.\venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"
```

Keep the generated signing secret out of source control. The default access
token lifetime is 15 minutes and the refresh session lifetime is 14 days. Set
`REFRESH_COOKIE_SECURE=true` when serving over HTTPS. CORS permits only the
configured `FRONTEND_ORIGIN` (default `http://localhost:5173`).

Install dependencies, apply the authentication schema migration, and start the
API:

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\alembic.exe upgrade head
.\venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Run the frontend in a second terminal:

```powershell
cd ..\Frontend
npm run dev
```

Set `VITE_API_BASE_URL` in the frontend environment if the API is not at
`http://localhost:8000`.

## Authentication API

`POST /api/auth/register` accepts:

```json
{
  "username": "organizer_user",
  "email": "user@example.com",
  "password": "StrongPassword123!"
}
```

Passwords must contain at least 12 characters, lower and uppercase letters, a
number, and a symbol. Registration returns the user ID, username, email, and
creation time. The password and password hash are never returned.

`POST /api/auth/login` accepts either email or username:

```json
{"identifier":"organizer_user","password":"StrongPassword123!"}
```

It returns an access token and profile, and sets the refresh token as an
HTTP-only cookie. Send the access token on protected requests:

```http
Authorization: Bearer <access_token>
```

`POST /api/auth/refresh` rotates the refresh cookie and returns a new access
token. `POST /api/auth/logout` revokes that refresh session and clears the
cookie. Access tokens are linked to the session in MySQL, so revoking a session
also invalidates access tokens from that session. `GET /api/auth/me` returns the
authenticated user's safe profile. Invalid credentials produce the same 401
response for unknown accounts and wrong passwords.

The React app keeps the access token in memory and relies on the HTTP-only
cookie to renew it. Authentication endpoints limit registration to five
attempts per IP per hour and login to ten per IP per fifteen minutes. These
limits are per application process; a multi-worker deployment should also
enforce limits at its shared reverse proxy or gateway.

## Protected file workflow

After login, scan with `POST /api/scans`:

```json
{"folder_path":"C:\\Data\\Documents"}
```

The server associates records with the authenticated account; requests do not
accept a trusted `user_id`. Use a returned `file_id` with
`POST /api/files/{file_id}/extract-content` and
`GET /api/files/{file_id}/content`. File queries include both the file ID and
authenticated user ID. The scan response includes its `source_folder_id` for
the existing bulk AI-analysis and organization-plan workflow. Unknown and
other-user files return 404.

The `POST` route always reopens the original file, extracts its current
contents, updates the one-to-one `file_contents` row, and returns that text.
The `GET` route only returns the most recently saved extraction. The response
includes `file_name`, `file_extension`, `extraction_status`, `extracted_text`,
`character_count`, `extractor_name`, and `extracted_at`. Extraction status is
`completed`, `truncated`, `empty`, `unsupported`, `requires_ocr`, or `failed`.
Text over `FILE_CONTENT_MAX_CHARS` (100,000 by default) is saved and returned
at that limit with status `truncated`, `truncated: true`, and a message; the
API does not imply that this is the complete source text. The file size limit
defaults to 10 MiB. Office archives are also capped at 100 MiB expanded size.

For example, if `notes.txt` contains `Machine learning enables computers to
learn patterns from data.`, call the extraction route as follows:

```powershell
curl.exe -X POST http://localhost:8000/api/files/123/extract-content `
  -H "Authorization: Bearer <access_token>"
```

The response includes the actual file text:

```json
{
  "file_id": 123,
  "file_name": "notes.txt",
  "file_type": ".txt",
  "file_extension": ".txt",
  "extraction_status": "completed",
  "files_extracted": 1,
  "records_persisted": 1,
  "failures": 0,
  "character_count": 63,
  "extracted_text": "Machine learning enables computers to learn patterns from data.",
  "truncated": false,
  "message": null,
  "extractor_name": "file-content-v1:txt",
  "extracted_at": "2026-10-23T12:00:00",
  "error": null
}
```

Extraction supports `.txt`, `.md`, `.csv`, `.json`, `.log`, `.xml`, `.html`,
`.htm`, `.yaml`, `.yml`, `.ini`, `.cfg`, `.conf`, `.py`, `.js`, `.ts`, `.tsx`,
`.css`, `.sql`, `.pdf`, `.docx`, `.xlsx`, and `.pptx`. It obeys
`FILE_CONTENT_MAX_BYTES` and `FILE_CONTENT_MAX_CHARS`, does not execute code,
and does not change original files.

The API also exposes per-file and bulk AI analysis and source-folder processing
routes. Authenticated chat is available at `POST /api/chat`. Send the latest
user message and up to 20 prior user/assistant messages:

```json
{
  "message": "What can you help me organize?",
  "history": [
    {"role": "user", "content": "Hello"},
    {"role": "assistant", "content": "I can help explain your folder scans and file analysis."}
  ]
}
```

The response is `{ "response": "...", "model": "gemma3:4b" }` (the model
field reflects the configured `OLLAMA_MODEL`). Chat turns are not persisted by
the API; the frontend keeps its chat history locally. A missing model, Ollama
connection failure, timeout, or invalid model response returns a clear HTTP
error without fabricating an assistant answer.

## Database migration

The migration adds a nullable unique `users.username` column so existing rows
remain intact, and creates `refresh_sessions` with hashed tokens, expiration,
and revocation timestamps. Run `alembic upgrade head` before using auth against
an existing MySQL database. Legacy records with no username remain email-only;
legacy plain-text passwords are not accepted.

## Verify MySQL records

In MySQL Workbench, select the configured `DB_NAME` and run:

```sql
SELECT DATABASE();
SELECT id, username, email, is_active FROM users;
SELECT user_id, expires_at, revoked_at, created_at FROM refresh_sessions;
SELECT COUNT(*) FROM files;
SELECT COUNT(*) FROM file_contents;
```

Refresh token values are not stored in MySQL; `refresh_sessions.token_hash`
contains only SHA-256 hashes.
